# Mission Reflection

The boot time and setup process of a Docker container is much faster compared to installing an operating system on a Virtual Machine. A traditional Virtual Machine has to boot a complete guest operating system, which usually takes several minutes and uses a lot of resources. In contrast, a Docker container starts in just a few seconds because it shares the host operating system kernel and does not need a full OS of its own. Port mapping using the -p 8080:80 option is necessary when running a web server inside a container. The Nginx server inside the container listens on port 80 by default, but that port is isolated inside the container. By mapping port 8080 on the host to port 80 inside the container, we can access the web server from outside using http://localhost:8080. When the docker rm command is used, the container is completely removed from the system. Any data stored inside the container that was not saved in a volume is also permanently deleted. This shows that containers are temporary by nature unless volumes are used to keep important data. Containerization changes the way software developers and IT operations teams work together in a DevOps environment. Developers can package their application together with all its dependencies into a single container image. The operations team can then run the exact same container in any environment. This reduces the common problem of “it works on my machine” and makes collaboration between the two teams much smoother and faster.
