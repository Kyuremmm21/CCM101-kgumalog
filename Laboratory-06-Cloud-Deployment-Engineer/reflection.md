# Mission Reflection

Writing a docker-compose.yml file makes a cloud engineer’s job much easier compared to manually typing commands. Instead of running several long docker run commands and remembering all the flags and links, I only need to define everything once in a YAML file. Then a single command (docker-compose up -d) deploys the whole stack. This is faster, less error-prone, and easy to share with teammates.
If I make an indentation error, such as using a Tab instead of spaces, the YAML file becomes invalid. Docker Compose will refuse to start and show an error about incorrect indentation. YAML is very strict about spacing, so even a small mistake can break the entire deployment.
We used environment variables (like MYSQL_PASSWORD and MYSQL_HOST) so that sensitive information and configuration details are not hard-coded inside the image. This makes the setup more flexible and secure. The same Compose file can be reused in different environments just by changing the values of the variables.
Deploying a fully functional enterprise cloud storage system like Nextcloud in just a few minutes felt very satisfying. It showed me the real power of containers and Infrastructure as Code. What used to take hours of manual setup can now be done with a few lines of code.
Since Mission 1, my understanding of Cloud Computing has grown a lot. I started by learning basic cloud concepts, then moved to single containers, and now I can deploy complete multi-tier applications. I now see that modern cloud engineering is more about writing code that describes infrastructure rather than clicking buttons or typing long commands one by one.
